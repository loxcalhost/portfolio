## Introduction

Silentium is a Linux machine that begins with discovering a hidden Flowise instance, where chaining an account takeover with an authenticated RCE grants initial access. From there, finding hardcoded credentials allows lateral movement via SSH password reuse, culminating in a root shell by exploiting an internally tunneled Gogs service.

## Attack Chain
- **Initial Access:** Virtual Host enumeration reveals a Flowise instance -> Exploitation of CVE-2025-58434 allows Account Takeover of an internal user -> Exploitation of CVE-2025-59528 (Authenticated RCE) grants a shell inside a container.
- **Lateral Movement:** Enumeration of environment variables reveals hardcoded SMTP credentials -> Password reuse allows SSH access to the host machine as the user `ben`.
- **Privilege Escalation:** Internal port scanning identifies a locally bound Gogs instance -> SSH local port forwarding exposes the service -> Exploitation of CVE-2025-8110 (Authenticated RCE via Symlink) yields a root shell.

Upon visiting the IP in the browser, it gives an error. To solve it, add:
```

```
to `/etc/hosts`

> **NOTE:** We need to add an entry to `/etc/hosts` because the domain `silentium.htb` is not publicly registered. When you visit the target IP in a browser using this domain, the system attempts to resolve it via public DNS servers. Since the domain does not exist publicly, DNS resolution fails. By adding the IP address and domain to `/etc/hosts`, you create a local mapping, allowing your system to resolve `silentium.htb` to the correct IP address without relying on external DNS servers.

Two non-standard application ports, 3000 and 3001, were identified as active on the target. Since these services are bound to localhost, they are not directly accessible externally; however, they can be accessed by establishing an SSH tunnel:
```
ssh -L 3001:127.0.0.1:3001 -L 3000:127.0.0.1:3000 ben@<ip_addr>
```

> **NOTE:** We used the `-L` parameter for local port forwarding.

## Mitigation and Remediation
- **Patch Management (Flowise & Gogs):** The initial foothold and final privilege escalation both relied on exploiting known vulnerabilities in outdated software. Flowise must be updated to version 3.0.6 or higher to patch CVE-2025-58434 and CVE-2025-59528. Similarly, Gogs should be updated to the latest stable release to resolve the symlink vulnerability (CVE-2025-8110).
- **Credential Management & Password Reuse:** Hardcoding plaintext credentials (such as `SMTP_PASSWORD` and `FLOWISE_PASSWORD`) in environment variables poses a significant security risk. Furthermore, the user `ben` reused these application credentials for his system SSH account. Organization-wide policies should enforce password complexity, prohibit password reuse, and mandate SSH key-pair authentication over password-based logins.
- **Principle of Least Privilege:** The Gogs web service was found running directly as the `root` user. Web applications and internal services should always be executed under dedicated, low-privileged service accounts (e.g., a `git` or `gogs` user). If this practice had been followed, the Gogs RCE exploit would have only granted limited access rather than immediate total system compromise.
